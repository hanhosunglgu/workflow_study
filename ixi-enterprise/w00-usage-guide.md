**대상 워크플로우**: `ixi-enterprise/w00-reference-list.json`
**생성기**: `ixi-enterprise/build-w00.py`
**작성일**: 2026-08-21
**환경**: 운영기 `https://ivms.lguplus.co.kr`
**관련 문서**: `12-flow-a-restructure-plan.md` 6.2절(계층 0), `08-ivms_openapi_spec.md` 1.5~1.7절

## 0. 이 플로우는 무엇인가

W0-1이 확정하는 참조값 3개(`orgId` / `templateNo` / `asstType`)의 **선택지 전체를 사람에게 보여주는 조회 전용 플로우**다.

| 구분 | W0-0 (본 문서) | W0-1 |
|---|---|---|
| 목적 | 후보를 **전부 나열** | 값을 **1개로 확정** |
| 출력 | 목록 | `orgId` / `orgNm` / `templateNo` / `asstType` |
| 실행 시점 | 값을 정할 때 1회 | 조직 구조 변경 시 |
| 판단 주체 | **사람** | Agent |

> **왜 나눴나**: W0-1에 목록 출력을 얹으면 26개 템플릿 전문이 컨텍스트에 들어오고 출력으로도 나간다. W0-1의 존재 이유가 체인을 짧게 유지하는 것이라 목적이 다른 조회는 분리했다.

### 🔴 이 플로우가 필요해진 계기

W0-1 첫 실행에서 `templateNo=151`이 나왔는데, 그 근거가 프롬프트의 **"배열 첫 번째 항목을 쓴다"**였다. 26개 후보 중 1번이 우연히 `151`이었을 뿐이고, 목록에는 `(구)`, `_bak`, `_복제본_1`, `_원본`, `w16테스트` 같은 항목이 섞여 있다. **API 반환 순서가 바뀌면 엉뚱한 템플릿이 선택되고 알아채기 어렵다.**

반면 `asstType`은 8개 항목이 전부 `SSRCCE`라 선택의 여지가 없고, `orgId`는 조직명 정확 일치로 확정되므로 순서 의존이 없다. **확인이 필요한 것은 사실상 `templateNo` 하나다.**

## 2. 질문 텍스트 전체 목록

프롬프트는 **키워드로 조회 종류를 판별**한다. 어느 것도 매칭되지 않으면 3가지를 모두 수행한다.

| 조회 | 트리거 키워드 |
|---|---|
| 조회 1 (템플릿) | 템플릿, templateNo, 진단항목 |
| 조회 2 (자산분류) | 자산분류, asstType, 카테고리 |
| 조회 3 (조직) | 조직, 팀, Lab, orgId |

```
진단템플릿 목록 전부 보여줘
```


## 3. 이 플로우로 할 수 없는 것

### 3.1 범위 밖 (프롬프트가 명시적으로 거부)

| 요청 | 결과 |
|---|---|
| 자산 목록 조회 | ❌ 수행하지 않음 — W1의 범위 |
| 취약점 조회 | ❌ 수행하지 않음 — W2의 범위 |
| "어떤 값을 써야 해?" | ❌ 권하지 않음 — 목록만 제시, 선택은 사람 |

마지막 항목은 의도된 설계다. **이 플로우는 값을 확정하지 않는다.** 확정은 W0-1이 하고, 무엇을 확정할지는 사람이 정한다.

### 3.2 현재 프롬프트의 고정값

아래는 프롬프트에 하드코딩되어 있어 질문으로 바꿀 수 없다. 필요하면 `build-w00.py`의 `SYSTEM_PROMPT`를 수정하고 재생성한다.

| 항목 | 고정값 | 바꾸려면 |
|---|---|---|
| `userId` | `admin` | 프롬프트 수정 |
| `asstCtgrLevel` | `L` (대분류) | `M`/`S`는 각 87건 — 프롬프트에 조회 4 추가 필요 |
| 조직 조회 시작점 | `pOrgId=org_002205` | 다른 부문을 보려면 프롬프트 수정 |
| `orgList` 호출 상한 | **3회** | 상향 시 컨텍스트 리스크 재검토 필요 |

### 3.3 🔴 orgList 호출 상한 3회

프롬프트가 `orgList` 호출을 **최대 3회로 제한**한다. 4차 실패(1,017,179 토큰) 이후 도입한 안전장치다.

따라서 아래 요청은 상한에 걸려 완결되지 않는다.

```
❌ 모든 Lab의 하위 팀을 전부 보여줘     (5회 필요)
❌ 전체 조직 트리를 다 펼쳐줘            (6회 이상 필요)
```

**대응**: Lab을 하나씩 나눠 질문한다.

```
✅ AX엔지니어링Lab 하위 팀 목록 보여줘
✅ AICC개발Lab 하위 팀 목록 보여줘
   ... (Lab마다 별도 실행)
```

## 4. 실행 후 판단 가이드

### 4.1 templateNo 확인 — 가장 중요

목록에서 **`151`의 이름이 `LG유플러스_기준항목(신규)`인지** 확인한다. 헷갈리기 쉬운 후보들이다.

| atemplateNo | 이름 | 비고 |
|---|---|---|
| **151** | LG유플러스_기준항목(신규) | 현재 사용 중 |
| 101 | (구)LG유플러스_기준항목 | 구버전 |
| 157 | LG유플러스_기준항목(Cloud) | 클라우드 전용 |
| 167 | LG유플러스_주요정보통신기반시설 | 기반시설 |
| 149 | LG유플러스_기준항목(암호점검) | 암호 점검 |

| 확인 결과 | 조치 |
|---|---|
| `151`이 맞다 | W0-1 프롬프트를 **이름 기반 조회로 변경 권장**(4.2절) |
| 다른 값이어야 한다 | W0-1 프롬프트에 해당 `templateNo`를 명시하고, W1/W2 상수도 함께 교체 |

### 4.2 권장 개선 — 순서 의존 제거

`151`이 맞더라도 현재 W0-1 프롬프트는 "**첫 번째 항목**"을 쓰므로 순서에 의존한다. 아래로 바꾸면 안전하다.

```
현재: templateList의 첫 번째 항목의 atemplateNo를 확정한다

변경: templateName이 "LG유플러스_기준항목(신규)"인 항목의 atemplateNo를 확정한다.
      없으면 목록 전체를 출력하고 사용자에게 선택을 요청한다
```

### 4.3 운영기/개발기 대조

본 문서의 기대 출력은 **개발기 실측값**이다. W0-1 첫 운영기 실행에서 산출값 4개(`org_000991` / `Enterprise SW프로덕트개발팀` / `151` / `SSRCCE`)가 개발기와 일치했으므로 목록도 같을 가능성이 높으나, **26건이라는 개수 자체는 운영기에서 다를 수 있다.**

| 대조 항목 | 개발기 |
|---|---|
| 진단템플릿 건수 | 26 |
| 자산분류 건수 | 8 (전부 `SSRCCE`) |
| Lab 건수 (`org_002205` 하위) | 5 |
| 팀 건수 (`org_001738` 하위) | 5 |

차이가 있으면 `12-flow-a-restructure-plan.md`의 환경 차이표에 기록한다.

## 5. 문제 발생 시

| 증상 | 원인 / 대응 |
|---|---|
| `msgCd: E` (필수 컬럼 확인 필요) | 파라미터 누락. `userId=admin` 전달 여부 확인 |
| 응답은 200인데 목록이 비어 있음 | 파라미터 조합이 어긋난 경우 IVMS는 오류가 아니라 **빈 값을 200으로 반환**한다(`guidelineCdInfo`에서 확인된 패턴). 호출 파라미터를 로그에서 확인할 것 |
| 401 / 인증 오류 | 인증 헤더 4종의 **키가 등록되어 있는지** 확인(값은 비워도 됨) |
| 타임아웃 | `read_timeout`이 30000인지 확인 |
| Agent가 목록을 요약해버림 | 프롬프트의 "전부 보여준다" 지시가 무시된 경우. 질문에 "전부", "전체"를 명시해 재시도 |
| `orgList` 호출이 3회를 넘음 | 상한이 지켜지지 않는 것. 프롬프트 [조회 3]의 상한 문구 확인 |

## 6. 재생성

```bash
python3 ixi-enterprise/build-w00.py            # 운영기 JSON 생성
python3 ixi-enterprise/build-w00.py --verify   # 생성 없이 구조 검증만
```

생성기는 **운영기 URL만** 만든다. 검증 항목 7종(노드 구성 / 엣지 참조 무결성 / Tool 연결 / 중괄호 / URL / tool_mode / 인증 헤더)을 통과해야 파일을 쓴다.

프롬프트를 바꾸려면 `build-w00.py`의 `SYSTEM_PROMPT` 상수를 수정하고 재생성한다. JSON을 직접 편집하면 엣지 참조나 `tool_mode`를 놓치기 쉽다.
